# PehRadar — Data Schema

**Status:** Draft v0.1 (M0). This is the target schema for the first Alembic migration (M3). Field names here are the source of truth for SQLAlchemy models, Pydantic schemas, and generated TypeScript types.

---

## 1. Conventions

- **IDs:** `id` is a UUIDv4 stored as `String(36)`. It is generated by the API, never by the client (except `client_request_id`).
- **Timestamps:** `DateTime(timezone=True)`, always UTC. Every table has `created_at`. Mutable tables also have `updated_at`.
- **Enums:** stored as `String` with a `CHECK (col IN (...))` constraint, so the same schema works on SQLite and Postgres (`Techspec.md` §11).
- **Coordinates:** `lat`/`lng` as `Float` (WGS84). `CHECK` that they are inside the Karachi bounding box `lat 24.70–25.30, lng 66.60–67.60` for cameras and stations. This enforces the Karachi-only scope at the data layer.
- **JSON:** SQLAlchemy generic `JSON`.
- **Naming:** snake_case tables, singular (`camera`, `incident`).
- **Deletion:** no hard deletes of incidents, detections, notifications, or timeline events in the app. Evidence can be purged by script (`evidence_frame` rows only).

## 2. Provenance model

Every record that represents something in the real world, or stands in for it, says where it came from:

| Field | Type | Values / meaning |
|---|---|---|
| `data_source` | enum `DataSource` | `SIMULATED` (invented for the demo), `OSM` (OpenStreetMap export), `PUBLIC_WEB` (manually transcribed from a public web page), `MANUAL_DEMO` (entered by the team for demo purposes, not representing a real facility) |
| `source_ref` | String(500), nullable | e.g. `osm:node/123456`, a URL, or `null` for SIMULATED |
| `licence` | String(50), nullable | e.g. `ODbL-1.0` for OSM |
| `verification_status` | enum `VerificationStatus` | `UNVERIFIED` (default) or `VERIFIED`. **No MVP record may be `VERIFIED`** unless someone independently confirmed it, and that confirmation must be recorded in `verification_note`. |
| `retrieved_at` | DateTime, nullable | When external data was fetched |

Derived records carry a simple flag:
- `analysis_job`, `detection_event`, `incident`: `is_simulated` (Boolean, NOT NULL). It is `true` whenever the camera is `SIMULATED`, which means always `true` in the MVP.
- `notification`: `is_test` (Boolean, NOT NULL, default `true`). A `CHECK (is_test = true)` constraint is applied in the MVP migration, so non-test notifications are impossible until the constraint is deliberately removed.

## 4. Entities

### 4.1 `camera`
| Field | Type | Constraints |
|---|---|---|
| `id` | String(36) | PK |
| `code` | String(20) | UNIQUE, NOT NULL, e.g. `KHI-SIM-01` |
| `name` | String(120) | NOT NULL, e.g. "Saddar — Empress Market (simulated)" |
| `area` | String(80) | NOT NULL, e.g. "Saddar" |
| `lat`, `lng` | Float | NOT NULL, Karachi bbox CHECK |
| `heading_deg` | Integer | NULL, 0–359 (for marker cone) |
| `status` | `CameraStatus` | NOT NULL, default `ACTIVE` |
| `default_sample_id` | String(64) | NULL, references `samples/manifest.json` id (not a DB FK) |
| `data_source` | `DataSource` | NOT NULL, `CHECK = 'SIMULATED'` in MVP |
| `source_ref`, `licence`, `verification_status`, `retrieved_at` | see §2 | |
| `created_at`, `updated_at` | DateTime | NOT NULL |

Simulated camera locations are approximate points at public places. They do not imply that any real camera exists there.

### 4.2 `fire_station`
| Field | Type | Constraints |
|---|---|---|
| `id` | String(36) | PK |
| `name` | String(160) | NOT NULL |
| `lat`, `lng` | Float | NOT NULL, Karachi bbox CHECK |
| `address_text` | String(300) | NULL (as given by source) |
| `is_active_in_demo` | Boolean | NOT NULL, default `true`. A demo toggle only, **not** a claim of real availability. |
| `data_source` | `DataSource` | NOT NULL (`OSM`, `PUBLIC_WEB`, or `MANUAL_DEMO`) |
| `source_ref` | String(500) | NOT NULL when `data_source != MANUAL_DEMO` |
| `licence` | String(50) | NULL |
| `verification_status` | `VerificationStatus` | NOT NULL, default `UNVERIFIED` |
| `verification_note` | String(500) | NULL; required by app logic if `VERIFIED` |
| `retrieved_at` | DateTime | NULL |
| `created_at`, `updated_at` | DateTime | NOT NULL |

UNIQUE(`data_source`, `source_ref`) keeps re-seeding idempotent.

**No phone numbers or contact details are stored.** Notifications go to `DEMO_RECIPIENTS` from configuration, not to station records.

### 4.3 `analysis_job`
| Field | Type | Constraints |
|---|---|---|
| `id` | String(36) | PK |
| `camera_id` | String(36) | FK → camera.id, NOT NULL |
| `source_type` | `AnalysisSourceType` | NOT NULL |
| `sample_id` | String(64) | NULL; required when `SAMPLE` |
| `upload_path` | String(300) | NULL; server-generated, cleared after deletion |
| `original_filename` | String(200) | NULL; sanitized, display only |
| `status` | `AnalysisJobStatus` | NOT NULL, default `QUEUED` |
| `video_duration_s` | Float | NULL |
| `frames_total_estimate` | Integer | NULL |
| `frames_processed` | Integer | NOT NULL, default 0 |
| `detector_name`, `detector_version` | String(80) | NOT NULL (snapshot at job start) |
| `config_snapshot` | JSON | NOT NULL. Thresholds used (`CONF_THRESHOLD`, `SAMPLE_FPS`, `AGG_*`) so results are reproducible. |
| `events_created_count`, `duplicates_count`, `suppressed_event_count` | Integer | NOT NULL, default 0 |
| `error_code` | `JobErrorCode` | NULL |
| `error_message` | String(500) | NULL, sanitized |
| `is_simulated` | Boolean | NOT NULL |
| `queued_at`, `started_at`, `finished_at` | DateTime | `queued_at` NOT NULL |
| `created_at`, `updated_at` | DateTime | NOT NULL |

Index: (`camera_id`, `status`) supports the `CAMERA_BUSY` check and camera history. Index: (`status`, `queued_at`) supports the worker queue scan.

### 4.4 `detection_event`
| Field | Type | Constraints |
|---|---|---|
| `id` | String(36) | PK |
| `camera_id` | String(36) | FK → camera.id, NOT NULL (denormalized from job for dedup queries) |
| `analysis_job_id` | String(36) | FK → analysis_job.id, NOT NULL |
| `status` | `DetectionStatus` | NOT NULL |
| `classes` | JSON | NOT NULL, non-empty list of `DetectionClass` |
| `peak_confidence` | Float | NOT NULL, CHECK 0–1 |
| `max_box_area` | Float | NOT NULL, CHECK 0–1 |
| `positive_frame_count` | Integer | NOT NULL, ≥ 1 |
| `first_offset_s`, `last_offset_s` | Float | NOT NULL, `last ≥ first` |
| `peak_offset_s` | Float | NOT NULL |
| `bboxes` | JSON | NOT NULL; peak-frame boxes `[{cls, conf, x, y, w, h}]` normalized 0–1 |
| `suggested_severity` | `Severity` | NOT NULL |
| `is_escalation` | Boolean | NOT NULL, default false |
| `duplicate_of_detection_id` | String(36) | FK → detection_event.id, NULL |
| `incident_id` | String(36) | FK → incident.id, NULL |
| `detector_name`, `detector_version` | String(80) | NOT NULL |
| `reviewed_at` | DateTime | NULL |
| `reviewed_by_label` | String(80) | NULL |
| `review_reason_code` | `RejectReason` | NULL; required when `REJECTED` |
| `review_note` | String(1000) | NULL |
| `is_simulated` | Boolean | NOT NULL |
| `created_at`, `updated_at` | DateTime | NOT NULL |

Constraints:
- `status = 'DUPLICATE'` ⇒ `duplicate_of_detection_id IS NOT NULL OR incident_id IS NOT NULL` (CHECK).
- `status = 'REJECTED'` ⇒ `review_reason_code IS NOT NULL` (CHECK).

Indexes: (`camera_id`, `status`, `created_at`) for dedup snapshots and queue. (`status`, `created_at`) for the dashboard review queue. (`incident_id`).

### 4.5 `evidence_frame`
| Field | Type | Constraints |
|---|---|---|
| `id` | String(36) | PK |
| `detection_event_id` | String(36) | FK → detection_event.id, UNIQUE, NOT NULL (1:1 in MVP) |
| `jpeg_bytes` | LargeBinary | NOT NULL, ≤ 300 000 bytes (app-enforced) |
| `width`, `height` | Integer | NOT NULL |
| `sha256` | String(64) | NOT NULL |
| `created_at` | DateTime | NOT NULL |

This is kept separate from `detection_event` so list queries never load image bytes. Purging evidence deletes these rows only. The UI then shows "Evidence purged".

### 4.6 `incident`
| Field | Type | Constraints |
|---|---|---|
| `id` | String(36) | PK |
| `reference` | String(20) | UNIQUE, NOT NULL, human-readable, e.g. `PR-20261017-0003` |
| `camera_id` | String(36) | FK → camera.id, NOT NULL |

| `status` | `IncidentStatus` | NOT NULL, default `OPEN` |

| `classes` | JSON | NOT NULL (union over attached detections) |
| `lat`, `lng` | Float | NOT NULL; copied from camera (approximate incident location = camera location in MVP) |

| `confirmed_by_label` | String(80) | NOT NULL |
| `confirmed_at` | DateTime | NOT NULL |

"At most one active incident per camera" is enforced in the service layer inside the transaction, not with a partial unique index (to keep the schema portable). This is covered by a test (AC-18).

Indexes: (`status`, `created_at`) for the active list. (`camera_id`, `status`) for the dedup snapshot.

### 4.9 `incident_timeline_event`
| Field | Type | Constraints |
|---|---|---|
| `id` | String(36) | PK |
| `incident_id` | String(36) | FK → incident.id, NOT NULL |
| `event_type` | `TimelineEventType` | NOT NULL |
| `occurred_at` | DateTime | NOT NULL (may be backdated for `DETECTION_CREATED`) |
| `actor_type` | `ActorType` | NOT NULL |
| `actor_label` | String(80) | NULL, e.g. "Operator A", "system", "recipient" |
| `detection_event_id` | String(36) | FK, NULL |
| `notification_id` | String(36) | FK, NULL |

This table is append-only. There are no update or delete code paths, and a test asserts that the repository exposes none. Index: (`incident_id`, `occurred_at`).

## 5. Relationships

```
camera 1───* analysis_job 1───* detection_event 1───0..1 evidence_frame
camera 1───* detection_event *───0..1 incident
detection_event 0..1───* detection_event         (duplicate_of)
camera 1───* incident 1───1 detection_event        (primary_detection)
incident *───0..1 fire_station                      (assigned_station)
incident 1───* route_estimate *───1 fire_station
incident 1───* notification *───1 fire_station
incident 1───* incident_timeline_event
```

## 6. Non-persisted configuration (not in DB)

| Item | Location | Why not DB |
|---|---|---|
| Sample video manifest | `samples/manifest.json` | Static, versioned with licences. |
| Demo recipients (addresses/URLs) | `DEMO_RECIPIENTS` env var | Keeps contact data out of the DB and out of API responses. |
| Detector thresholds | env vars (snapshotted into `analysis_job.config_snapshot`) | Tunable without migration, but each job stays reproducible. |

## 7. Data deliberately **not** stored

- Raw uploaded videos (deleted after the job).
- Un-annotated full-resolution frames beyond the single evidence frame.
- Faces, person identities, licence plates, or any biometric data.
- Operator accounts, emails, or passwords. The operator is a free-text label.
- Recipient email addresses or webhook URLs.
- Plain-text ack tokens.
- Fire station phone numbers or staff names.

## 8. Seed data

| File | Contents | Provenance |
|---|---|---|
| `apps/api/seed/cameras.json` | 8 simulated cameras across Karachi (e.g. Saddar, Clifton, Korangi Industrial Area, SITE Area, Gulshan-e-Iqbal, North Nazimabad, Lyari, Gulistan-e-Jauhar) at approximate public locations | `SIMULATED` |
| `apps/api/seed/stations.json` | Fire stations from the OSM export, plus manual additions if needed | `OSM` / `PUBLIC_WEB`, all `UNVERIFIED` |

The seed loader is idempotent (upsert by `code` / (`data_source`, `source_ref`)). There is no seeded incident data. Incidents only come from running the pipeline, so nothing pretends to be a historical real incident.
