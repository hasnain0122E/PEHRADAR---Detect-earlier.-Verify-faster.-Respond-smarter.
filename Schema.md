# PehRadar — Data Schema

**Status:** v0.2 (M3, 2026-10-17). §4 is **implemented** by Alembic migration `0001` (`apps/api/alembic/versions/0001_m3_operational_schema.py`) and the ORM in `apps/api/app/models/tables.py`, which are the source of truth.
- The M3 brief simplified the M0 draft: lowercase status vocabularies, an incident state machine with `station_selected`, and evidence stored on the detection row.
- Tables not built yet are kept under **Planned** and will be revised when their milestone starts.

---

## 1. Conventions

- **IDs:** `id` is a UUIDv4 stored as `String(36)`. It is generated by the API, never by the client (except `client_request_id`).
- **Timestamps:** `DateTime(timezone=True)`, always UTC. Every table has `created_at`. Mutable tables also have `updated_at`.
- **Enums:** lowercase strings (M3) stored as `String` with a `CHECK (col IN (...))` constraint, so the same schema works on SQLite and Postgres (`Techspec.md` §11).
- **Coordinates:** `latitude`/`longitude` as `Float` (WGS84). `CHECK` that they are inside the Karachi bounding box `lat 24.70–25.30, lng 66.60–67.60` for cameras, stations and incidents. This enforces the Karachi-only scope at the data layer.
- **JSON:** SQLAlchemy generic `JSON`.
- **Naming:** snake_case tables, singular (`camera`, `incident`).
- **Deletion:** no hard deletes of incidents, detections, notifications, or timeline events in the app. Evidence can be purged by script (`evidence_frame` rows only).

## 2. Provenance

- **Cameras:** `is_simulated = true` for every MVP camera. Approximate public places; no real camera is implied.
- **Fire stations:** real locations from OpenStreetMap.
  - Each station records `data_source = osm`, `source_ref = osm:<type>/<id>`, `licence = ODbL-1.0` and `verification_status = unverified`.
  - `status` (`available` / `unavailable`) is a **demo flag**, never a claim about real availability or response capability. The API repeats this in `status_note`.
- **Detections and incidents:** carry `is_simulated`, copied from the camera.
- **Verification:** no record may be `verified` unless someone independently confirms it.

## 3. Vocabularies (`app/domain/incident_rules.py`)

| Name | Values |
|---|---|
| Camera status | `active`, `offline`, `maintenance` |
| Station status | `available`, `unavailable` (demo flag) |
| Detection / incident event type | `fire`, `smoke`, `fire_smoke` (from the model's two classes) |
| Detection review status | `pending`, `confirmed`, `rejected` |
| Severity | `low`, `medium`, `high` |
| Incident status | `detected` (reserved; unused in M3), `confirmed`, `station_selected`, `notified`, `acknowledged`, `resolved`, `rejected` |
| Timeline event type | `detection_created`, `operator_confirmed`, `station_selected`, `no_station_available`, `status_changed`, `resolved`, `rejected` |
| Timeline actor | `system`, `operator` |

## 5. Relationships (M3)

```
camera 1───* detection_event 1───0..1 incident (UNIQUE detection_event_id)
camera 1───* incident *───0..1 fire_station (assigned_station)
incident 1───* incident_timeline_event (ordered by seq)
```

## 6. Rules stored as code, not data

- **Severity:** `fire_smoke` → high; `fire` → high at confidence ≥ 0.70, otherwise medium; `smoke` → medium at ≥ 0.80, otherwise low.
- **Station selection:** the nearest station with `status = available` by Haversine distance from the incident (camera) coordinates. Ties break on id. Method `straight_line_haversine`, `is_driving_eta = false`.
- **State machine:** see `Appflow.md` §3.2.

## 7. Data deliberately **not** stored

- Raw uploaded videos (deleted after processing).
- Frames other than the single annotated evidence JPEG.
- Faces, identities, licence plates or other biometric data.
- Operator accounts or passwords. The operator is a free-text label; writes use one shared `OPERATOR_API_KEY`, which is never stored in the DB.
- Fire station phone numbers or staff names.
- Recipient addresses (notifications are not built yet).

## 8. Seed data

- **File:** `apps/api/seed/karachi_demo.json`, loaded by `python -m app.seed`.
- **Idempotent:** it inserts missing rows by deterministic id and refreshes descriptive fields, but never overwrites `status`.

| Records | Contents | Provenance |
|---|---|---|
| 8 cameras `KHI-CAM-01…08` | Saddar, Clifton, Korangi Industrial Area, SITE, Gulshan-e-Iqbal, North Nazimabad, Lyari, Gulistan-e-Jauhar | simulated, approximate public places |
| 5 stations `KHI-FS-01…05` | Saddar, Gulshan-e-Iqbal, Landhi, Orangi and Nazimabad fire stations | OSM (ODbL-1.0) via Overpass on 2026-10-17, unverified |

No incidents or detections are seeded. They only come from running the detector, so nothing poses as a real historical incident.
